# Веб-сервис «Автоматизированный прокат СИМ»

Проектная документация на разработанный функционал веб-сервиса автоматизированного проката средств индивидуальной мобильности (самокатов и велосипедов). Проект реализован в рамках учебного модуля 5 на базе технологий **PHP** и методологии **БЭМ**.

---

## 1. Общие сведения
Настоящий документ содержит описание функционального назначения, архитектуры, структуры данных и основных методов веб-сервиса «Автоматизированный прокат СИМ».

Программное средство реализовано как веб-приложение:
*   **Backend / API:** Чистый PHP 8.x (архитектура на базе PDO).
*   **Frontend:** HTML5, CSS3 с использованием методологии **БЭМ** (без использования сторонних тяжелых JavaScript-фреймворков для сохранения легкости структуры).

---

## 2. Функциональное назначение
Информационная система предназначена для автоматизации процессов проката СИМ, включая мониторинг доступного транспорта на карте-схеме, бронирование, управление поездками и учетными записями. 

### Ролевая модель:
*   **Клиент** — имеет доступ к интерактивной схеме, поиску доступных СИМ, истории своих поездок, балансу кошелька и управлению текущей арендой.
*   **Менеджер** — осуществляет контроль технического состояния СИМ, изменение тарифов и обработку заявок от пользователей.
*   **Администратор** — обладает полными правами по управлению всей системой, включая блокировку, разблокировку и создание учетных записей сотрудников.

### Безопасность и авторизация:
*   Обязательный ввод логина (Email) и пароля.
*   Защита от ботов с помощью интерактивной капчи-пазла.
*   **Автоматическая блокировка:** при трех последовательных неудачных попытках входа (неверный пароль или ошибка сборки капчи) учетная запись временно блокируется. Разблокировка выполняется только Администратором.

## 5. Описание базы данных
Для хранения данных используется реляционная СУБД MySQL. Имена таблиц и полей используют стандартный змеиный регистр (`snake_case`). Работа с БД происходит через расширение PHP PDO.

### Состав таблицы `users` (Пользователи):

| Поле (snake_case) | Тип данных | Назначение | Примечание |
| :--- | :--- | :--- | :--- |
| `user_id` | INT | Уникальный идентификатор | Первичный ключ (AUTO_INCREMENT) |
| `full_name` | VARCHAR(255) | Полное имя / ФИО пользователя | Обязательное поле |
| `email` | VARCHAR(150) | Уникальный Email в системе | Используется для авторизации, UNIQUE |
| `password_hash` | VARCHAR(255) | Криптографический хэш пароля | Создается через `password_hash()` |
| `role` | VARCHAR(50) | Роль в веб-сервисе | Клиент, Менеджер, Администратор |
| `failed_attempts` | TINYINT | Число неудачных попыток входа | Блокировка при значении >= 3 |
| `is_blocked` | TINYINT(1) | Флаг блокировки аккаунта | 0 — активен, 1 — доступ закрыт |
| `created_at` | TIMESTAMP | Дата и время регистрации | Заполняется автоматически |

## 6. Алгоритмы и бизнес-логика
1.  **Авторизация:** Проверка заполнения полей `email` и `password`.
2.  **Валидация капчи:** Серверная часть PHP сверяет переданный массив индексов `$_POST['puzzle_order']` с эталонным значением из `$_SESSION['captcha_order']`. При ошибке блок `.auth-form` получает БЭМ-модификатор `.auth-form--invalid-captcha`.
3.  **Верификация данных:** Запрос пользователя по Email. Если `is_blocked = 1`, алгоритм мгновенно возвращает ошибку. Проверка пароля выполняется через `password_verify()`.
4.  **Блокировка перебора:** При несовпадении пароля/капчи увеличивается `failed_attempts`. При значении `>= 3` выставляется флаг `is_blocked = 1`, а блок формы переключается в состояние `--blocked`.

## 7. Используемые методы бэкенда (PHP)
*   `loginUser($email, $password, array $puzzleOrder)` — Выполняет комплексную проверку капчи через `$_SESSION`, верификацию пароля и статуса блокировки.
*   `getAvailableSims($lat, $lng, $radius)` — Возвращает список доступных СИМ для рендеринга на БЭМ-блоке `.map-view`.
*   `startRent($simId, $userId)` — Инициирует аренду, переводит статус СИМ в 'active_rent'.
*   `endRent($rentId, $currentLat, $currentLng)` — Завершает поездку, рассчитывает стоимость и списывает средства со счета клиента.
*   `unlockUser($userId)` — Снимает блокировку с аккаунта (доступно только Администраторам).

---

## 8. Надежность и обработка ошибок
*   При падении интернет-соединения сессия проката сохраняется на сервере, а списание корректируется по фактическим координатам СИМ.
*   Критические системные сбои логируются через `error_log`.
*   Пользователю возвращаются понятные сообщения об ошибках, которые динамически выводятся в БЭМ-элемент `.auth-form__error-message--visible`.

## 9. Порядок развертывания и запуска
1. Склонируйте репозиторий проекта на ваш локальный сервер (Apache/Nginx):
   ```bash
   git clone https://github.com
   ```
2. Импортируйте структуру базы данных и демонстрационные данные из файла `database.sql` в вашу СУБД MySQL.
3. Откройте файл `config.php` и настройте параметры подключения к СУБД (хост, имя базы данных, логин и пароль от локального сервера MySQL).
4. Запустите локальный сервер и перейдите по адресу проекта (например, `http://localhost/sim-rent-project/`).
